# abify

abify is a multi-tenant conversion-optimization platform. It lets teams run A/B, split-URL and multivariate tests on their websites, see where visitors click with heatmaps, and watch real sessions with replay. Revenue can be attributed to each variation through a Shopify integration, a server-side API or Google Tag Manager.

Built with Laravel 13, Inertia, React 19 and Tailwind CSS 4.

## Features

- **Experiments.** A/B, split-URL and multivariate tests, each with variations, goals, URL targeting and deterministic visitor bucketing.
- **Analytics.** Per-experiment results by variation, with date-range filtering and revenue when goals carry order data.
- **Heatmaps.** Click and scroll data drawn over a real page screenshot, captured with headless Chrome and segmented by desktop, tablet and mobile.
- **Session recordings.** Replay powered by rrweb, with a daily capture quota, client-side sampling, a maximum duration and automatic retention pruning.
- **Integrations.**
  - Shopify: an `orders/paid` webhook verified by HMAC, plus a theme app extension.
  - Google Analytics 4 and the GTM dataLayer: experiment assignments and conversions.
  - Server-to-server conversions API, authenticated by a per-site write key.
- **Accounts and billing.** Companies with invited users, super-admin tools with impersonation, Stripe subscriptions through Cashier, and a 14-day trial.
- **Authentication.** Email and password, Google sign-in, two-factor authentication and passkeys.

## Architecture

**Database per company.** The default connection holds users, companies, sites, experiments and billing. Each company also gets its own physical database, which holds the high-volume tracking data: assignments, analytics events, heatmap data, conversions and recordings. `App\Support\Tenancy\TenantManager` points the `tenant` connection at the right database for each request.

**Tracking pipeline.** A customer pastes a small snippet on their site. It hides the page, loads `/t/{siteId}.js`, applies the visitor's variation, and reveals the page again on timeout or error. The script then sends events to `/api/t/collect`. Replay chunks go to `/api/t/rec` and are written to disk, never to the database. The recorder is a separate bundle, served at `/t/recorder.js`, so rrweb never delays the page.

**Frontend.** Inertia pages live in `resources/js/pages`. Typed routes are generated by Laravel Wayfinder into `resources/js/routes` and `resources/js/actions`. Do not edit those files by hand.

```
app/
  Actions/        Tenant provisioning, conversion recording, recording quota
  Console/        tenant:migrate, tenant:provision, recordings:prune
  Http/           Dashboard, tracking, Shopify and admin controllers
  Jobs/           Event storage, page screenshots, GA4 conversions
  Models/         Central models; Models/Tenant holds per-company tracking models
  Support/        Tenancy, tracking script renderer, screenshots, analytics
config/           billing, recordings, screenshots, shopify
database/
  migrations/         Central database
  migrations/tenant/  Per-company databases
resources/js/     React app plus the standalone recorder bundle
shopify-app/      Shopify app manifest and theme extension
docs/             Integration guides
```

## Requirements

- PHP 8.3 or newer
- Composer 2
- Node.js 22 or newer
- MySQL or MariaDB. Tenant databases require MySQL-compatible SQL.
- Google Chrome or Chromium, for heatmap screenshots
- A Stripe account, for billing

## Getting started

```bash
composer setup     # install dependencies, create .env, generate a key, migrate, build assets
composer dev       # start the development servers
```

`composer setup` copies `.env.example` to `.env` if none exists. Before running it, create a database and set the `DB_*` values in `.env`.

Start a queue worker if you turn on queued screenshots or other queued jobs:

```bash
php artisan queue:listen
```

### Tenant databases

Each company's database is provisioned when the company is created. To provision or re-provision one by hand, and to migrate every tenant database after adding a tenant migration:

```bash
php artisan tenant:provision {company_id}
php artisan tenant:migrate
```

Central migrations use the normal `php artisan migrate`. Tenant migrations live in `database/migrations/tenant`.

## Configuration

Copy `.env.example` and fill in the values you need. Never commit `.env`.

| Area | Variables |
| --- | --- |
| Database | `DB_*`, and optionally `TENANT_DB_HOST`, `TENANT_DB_PORT`, `TENANT_DB_USERNAME`, `TENANT_DB_PASSWORD`. Leave `DB_TENANT_DATABASE` blank, because it is set at runtime. |
| Stripe | `STRIPE_KEY`, `STRIPE_SECRET`, `STRIPE_WEBHOOK_SECRET`, `CASHIER_CURRENCY`, and the `STRIPE_PRICE_BASIC_*` and `STRIPE_PRICE_GROWTH_*` price IDs |
| Google sign-in | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` |
| Screenshots | `CHROME_BINARY`, `SCREENSHOT_QUEUE`, `SCREENSHOT_DISK` |
| Recordings | `RECORDING_DISK`, `RECORDING_DAILY_LIMIT`, `RECORDING_SAMPLE_RATE`, `RECORDING_MAX_DURATION_MINUTES`, `RECORDING_RETENTION_DAYS` |
| Shopify | `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SHOPIFY_SCOPES`, `SHOPIFY_API_VERSION` |

### Plans

Plan limits are defined in `config/billing.php`. Stripe holds the amounts actually charged, so keep the advertised prices in that file in step with Stripe by hand.

| Plan | Sites | Tests per site | Heatmap sessions per month | Recordings per day |
| --- | --- | --- | --- | --- |
| Trial (14 days) | 1 | 1 | 1,000 | 10 |
| Basic ($10/mo or $100/yr) | 5 | 50 | 2,000 | none |
| Growth ($50/mo or $500/yr) | 15 | 200 | 10,000 | 100 |

## Installing on a website

Each site gets a snippet in its overview page. Paste it as high in the `<head>` as possible. After it loads, the page exposes a small API:

```js
abify('track', 'signup_clicked', { plan: 'pro' });          // custom event
abify('goal', 42, { revenue: 99, currency: 'USD', order_id: 'A-1001' });  // conversion
```

Conversions are deduplicated on `order_id`. For a Google Tag Manager setup, including GA4 reporting by variation, see [docs/gtm-template.md](docs/gtm-template.md).

### Server-side conversions

```
POST /api/v1/conversions
```

Authenticate with the site's write key. Requests are throttled per site rather than per IP.

### Shopify

The theme extension and app manifest are in `shopify-app/`. Deploy them with the Shopify CLI from that directory:

```bash
shopify app deploy
```

Purchases are recorded from the `orders/paid` webhook and matched to a visitor through the `_abify_vid` cart attribute. Create a goal with the key `purchase` on any experiment you want measured by revenue.

## Scheduled tasks

`recordings:prune` deletes recordings past their retention window and runs daily at 03:15. Make sure the Laravel scheduler is running:

```bash
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1
```

## Deployment notes

- Set `APP_ENV=production` and `APP_DEBUG=false`, then run `php artisan migrate --force` and `php artisan tenant:migrate`.
- Run a queue worker and set `SCREENSHOT_QUEUE=true`, so screenshots do not block requests.
- Move recordings and screenshots to object storage by setting `RECORDING_DISK` and `SCREENSHOT_DISK` to `s3`.
- Point a Stripe webhook at the Cashier endpoint and set `STRIPE_WEBHOOK_SECRET`.
- Install Chrome or Chromium on the host and set `CHROME_BINARY` if it is not at `/usr/bin/google-chrome`.
